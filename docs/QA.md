## 0. 테스트 안전 수칙 (제일 먼저 지킨다)

이전에 보안 테스트 중 **고아 데이터**(지울 수 없는 문서)가 생긴 적이 있다. 재발 방지 규칙:

1. **실제 학급(`TEST-1` = 2학년 5반, classId `q5pZ…`)에는 쓰지 않는다.** 읽기만 한다.
2. 쓰기 테스트는 **QA 전용 학급**(`classes/QA-TMP…`, 입장 코드 `QA-TMP…`) 안에서만 한다.
   - 이 학급은 테스트 시작 시 만들고 **끝나면 하위 문서까지 전부 지운다.**
   - `analyses` 삭제는 **교사만** 가능하므로(`firestore.rules`), QA 학급의 `teacherUid`는
     테스트에 쓰는 계정 uid로 둔다. 그래야 만든 문서를 스스로 지울 수 있다.
3. **존재하지 않는 학급 아이디에는 절대 쓰지 않는다.** §5.2 — 부모 문서가 없으면
   삭제 규칙의 `isTeacherOf`가 부모를 못 찾아 **앱에서 영영 못 지운다.**
   "거부되어야 하는" 테스트라도 만에 하나 통과하면 고아가 된다.
4. 만든 문서 ID는 만들자마자 §7 실행 기록의 **정리 대상 목록**에 적고,
   세션 종료 전 **목록이 비었는지 확인**한다.
5. 수집기 테스트는 업로드 대상 학급 코드를 반드시 **QA 전용 코드**로 넣는다.

**1회차에서 추가로 배운 것**
6. 브라우저 자동화로 검증할 때 `#해시`만 바꾸는 이동은 **페이지를 다시 읽지 않는다.**
   Firestore에서 문서를 지운 뒤 화면 상태를 확인하려면 반드시 `location.reload()`를 부른다.
   (1회차에서 이것 때문에 "설계 관문이 안 걸린다"고 잘못 판단할 뻔했다.)
7. "남이 만든 문서" 권한 시험은 두 번째 익명 계정을 REST(`accounts:signUp`)로 따로 발급해
   쓴다. 브라우저 세션에서 로그아웃하면 QA 학급의 `teacherUid`가 바뀌어 **정리를 못 하게 된다.**
