## 1. 사용자 입력을 HTML로 해석하지 않도록 표시

**문제**

측정 제목·조건·사건 이름 등을 `innerHTML` 문자열에 직접 넣는 경로가 있다. 저장된 문자열에 HTML이 포함되면 학생 화면뿐 아니라 교사 데이터 관리 화면에서도 해석될 수 있다. 이벤트 속성 등을 포함한 입력은 저장형 XSS로 이어질 수 있다.

**관련 코드**

- [public/js/teacher-tabs.js](../public/js/teacher-tabs.js): `renderManageTab()`의 측정 제목 표시
- [public/js/exp1.js](../public/js/exp1.js): 측정 목록과 기본 정보 표
- [public/js/exp2.js](../public/js/exp2.js), [exp3.js](../public/js/exp3.js), [exp4.js](../public/js/exp4.js): 같은 형태의 데이터 표시 경로
- [collector/static/measure.js](../collector/static/measure.js): 채널 이름표·제목 표시

**개선 방향**

정적 화면 구조와 사용자 입력을 분리하고, 사용자 입력은 DOM의 `textContent` 또는 입력 요소의 `value`로 넣는다. 한 화면만 고치지 않고 저장 데이터가 표시되는 모든 경로를 확인한다.

**검증 항목**

- HTML 태그, 따옴표, 이벤트 속성이 포함된 제목을 표시해도 코드가 실행되지 않는다.
- 학생 목록·정보 표·교사 관리 화면·수집기 채널 목록에서 입력이 문자 그대로 보인다.

## 2. 자동 저장 상태·실패·미저장 이탈 처리

**문제**

`steps.js`는 입력 1초 뒤 `onSave(analysis)`를 호출하지만 반환 Promise의 성공·실패를 처리하지 않는다. 저장 실패를 학생이 알기 어렵고, 마지막 입력 직후 새로고침하면 아직 전송되지 않은 답변이 사라질 수 있다. 측정 선택·그래프 설정 등에도 저장 결과를 기다리지 않는 호출이 있다.

**관련 코드**

- [public/js/steps.js](../public/js/steps.js): `queueSave()`, `saveNow()`
- [public/js/data.js](../public/js/data.js): `saveAnalysis()`
- 실험 1~4 및 사건 메모의 `saveAnalysis` 호출부

**개선 방향**

- 공통 저장 흐름에서 `저장 중 / 저장됨 / 저장 실패`를 표시한다.
- 저장 실패 후 답변을 유지하고 재시도할 수 있게 한다.
- 미저장 변경이 있는 경우 페이지 이탈 경고를 제공한다.
- 화면 전환·재조회 전에 대기 중인 저장과 진행 중인 저장을 어떻게 처리할지 명확히 한다.
- 페이지 종료 시 비동기 저장 호출만으로 저장 완료를 보장한다고 가정하지 않는다.
- 측정 데이터를 `localStorage`에 저장하지 않는 기존 원칙을 유지한다.

**검증 항목**

- 저장 거부·통신 실패 시 실패 표시와 재시도가 동작한다.
- 입력 직후 새로고침·학급 나가기·실험 전환 시 미저장 상태가 조용히 사라지지 않는다.
- 오래 걸린 저장 응답이 최신 저장 상태를 잘못 표시하지 않는다.

## 3. 업로드 재시도의 중복 저장 방지

**문제**

실시간 측정은 센서별로 새 문서를 순서대로 생성한다. 첫 센서 업로드는 성공하고 두 번째 센서는 실패하면 재시도 시 첫 센서도 새 문서로 저장된다. 서버 저장 후 응답만 끊긴 경우에도 중복이 생길 수 있다. 업로드 완료 상태에서 다시 호출하는 경우를 막는 서버 측 처리도 필요하다.

**관련 코드**

- [collector/main.py](../collector/main.py): `api_upload()`
- [collector/uploader.py](../collector/uploader.py): `upload_dataset()`
- [collector/templates/index.html](../collector/templates/index.html): 서버로 보내기 버튼

**개선 방향**

- 측정·채널별 문서 ID를 업로드 전에 정하고 재시도에도 유지한다.
- 이미 저장된 문서는 동일 측정인지 확인하고 기존 결과를 반환한다.
- 부분 성공 결과를 보존해 재시도 범위를 명확히 한다.
- 재시도 시 익명 인증 UID가 달라지는 현재 흐름과 원본 수정 금지 규칙을 함께 고려한다. 고정 ID로 단순 덮어쓰는 방식만으로 해결하지 않는다.
- 버튼 비활성화는 보조 수단으로 사용하고 중복 방지는 업로드 경로에서 보장한다.

**검증 항목**

- 여러 센서 중 두 번째 업로드만 실패한 뒤 재시도해도 문서 수가 늘어나지 않는다.
- 서버 저장 후 응답 유실을 모의해도 같은 측정이 한 번만 남는다.
- 업로드 완료 후 재호출해도 기존 원본이 변경되지 않는다.

## 4. 교사 측정 목록 갱신 및 실패 캐시 제거

**문제**

같은 학급의 측정 목록 캐시는 만료되지 않고 데이터 삭제 때만 명시적으로 비워진다. 탭 전환은 표시 상태만 바꾼다. 학생이 새로 측정해도 교사 일반 탭은 기존 목록을 계속 보여줄 수 있다. 최초 조회가 실패하면 실패한 Promise도 캐시에 남는다. 별도의 교실 화면용 실시간 뷰는 주기적으로 다시 조회한다.

**관련 코드**

- [public/js/teacher-tabs.js](../public/js/teacher-tabs.js): `getDatasets()`, `invalidateDatasetsCache()`
- [public/js/teacher.js](../public/js/teacher.js): `switchTab()`

**개선 방향**

우선 새로고침 버튼을 제공해 캐시를 비우고 측정·분석을 다시 조회한다. 실패한 Promise는 캐시에서 제거한다. 자동 갱신이 필요하면 실제 수업 운영에 맞는 간격을 정한다.

**검증 항목**

- 학생 업로드 후 교사 화면에서 새로고침하면 새 측정이 보인다.
- 첫 조회가 실패해도 다음 시도는 실제 조회를 수행한다.
- 학급을 바꾸는 동안 늦게 도착한 이전 학급 응답이 현재 화면을 덮지 않는다.

## 6. 종합 그래프의 센서·단위 구분 및 실험 4 추가

**문제**

교사 종합 그래프는 실험별로 모둠의 최신 측정 하나를 고른 뒤 첫 데이터의 센서·단위를 전체 축에 적용한다. 같은 실험에 온도와 CO₂ 등 서로 다른 측정이 들어오면 비교할 수 없는 값을 같은 축에 표시할 수 있다. 실험 선택 목록에도 실험 4가 빠져 있다.

**관련 코드**

- [public/js/teacher-tabs.js](../public/js/teacher-tabs.js): `renderChartTab()`

**개선 방향**

센서·단위가 같은 데이터만 비교하도록 필터를 제공한다. 필요한 경우 조건도 구분한다. 실험 선택지는 기존 실험 목록 정의에서 생성해 실험 4를 포함한다.

**검증 항목**

- 같은 실험에 서로 다른 단위의 데이터가 있어도 한 축에 섞이지 않는다.
- 선택한 센서가 없는 모둠은 다른 센서 값으로 대신 표시되지 않는다.
- 실험 4를 선택하고 온도 데이터를 비교할 수 있다.

## 7. 측정 한도 도달 시 안전한 종료

**문제**

4,500점부터 경고하지만 측정은 계속된다. 5,000점을 넘기면 업로드 검증이 전체 데이터를 거부한다. 경고를 놓치면 수업 시간 동안 모은 값을 정상 경로로 저장하지 못한다.

**관련 코드**

- [collector/main.py](../collector/main.py): `NEAR_LIMIT_POINTS`, 측정 상태 조회
- [collector/sensor.py](../collector/sensor.py): 측정값 누적 및 마지막 버킷 확정
- [collector/uploader.py](../collector/uploader.py): `validate()`

**개선 방향**

한도 도달 시 안전하게 자동 종료하고 저장 안내를 표시한다. 종료하면서 확정되는 마지막 버킷까지 포함해 한도를 넘지 않도록 한다. 다중 센서는 비교 시각이 어긋나지 않도록 함께 종료하는 방식을 검토한다. CSV·수동 입력도 저장 불가능한 양을 받은 뒤에야 오류를 내지 않도록 입력 시 검증한다.

**검증 항목**

- 4,999점·5,000점 경계에서 종료 후 실제 업로드할 데이터가 한도 이내다.
- 경고 화면을 확인하지 않아도 한도 초과 측정이 계속되지 않는다.
- 원본을 조용히 잘라내거나 버리지 않는다.

## 9. 화면 전환 시 차트 인스턴스 정리

**문제**

공통 차트 함수는 같은 캔버스에 다시 그릴 때만 기존 차트를 제거한다. 단계 전환으로 캔버스를 없애거나 실험 4처럼 새 캔버스를 생성하는 경로에는 이전 차트 정리가 없다. 반복 사용 시 차트 인스턴스와 관련 자원이 남을 가능성이 있다.

**관련 코드**

- [public/js/chart-kit.js](../public/js/chart-kit.js): `renderChart()`
- [public/js/exp4.js](../public/js/exp4.js): `drawChart()`
- [public/js/router.js](../public/js/router.js), [steps.js](../public/js/steps.js): 화면 교체

**개선 방향 및 검증**

캔버스 교체 전에 차트를 제거하거나 기존 캔버스를 재사용한다. 필요한 화면 정리 함수를 최소한으로 연결한다. 단계·탭·그래프 종류를 반복 전환한 뒤 차트 인스턴스가 계속 증가하지 않는지 브라우저에서 확인한다.

## 10. 반복 코드의 작은 단위 통합

실험 1~4에 반복되는 스타일, 측정 목록, 시간 표시, 기울기 계산 등을 작은 단위부터 통합한다. 특히 JavaScript가 삽입하는 공통 스타일을 기존 CSS로 옮기면 수정 위치가 명확해진다.

전체 실험을 처리하는 큰 범용 엔진이나 새로운 프레임워크는 우선 도입하지 않는다. 실험별 교육 질문과 계산 의미는 유지하고 실제로 같은 동작만 공유한다. 코드에서 참조되지 않는다는 이유만으로 CLI 진입점 등 사람이 직접 사용하는 기능을 삭제하지 않는다.

검증은 실험별 대표 데이터의 계산 결과, 빈 데이터 처리, 측정 선택과 화면 전환을 중심으로 수행한다.
